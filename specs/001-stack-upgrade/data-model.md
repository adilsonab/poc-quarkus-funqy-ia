# Data Model: Migração segura da stack

## Existing persisted entity

### Task

Represents one task exposed by the Funqy functions.

| Field | Database representation | Constraints and behavior |
|---|---|---|
| `id` | `BIGINT`, auto-increment primary key | Required, generated by PostgreSQL |
| `title` | `VARCHAR(255)` | Required; service trims surrounding whitespace and rejects blank or longer-than-255-character titles |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | Required; defaults to `CURRENT_TIMESTAMP` |

The canonical existing schema is the Liquibase changeset
`001-create-tasks` in
`src/main/resources/db/changelog/db.changelog-master.xml`. The migration does
not change this schema. The PostgreSQL major-version upgrade must restore the
existing rows and the Liquibase history before the application starts.

## Migration data

### PostgreSQL 17 backup

- One logical custom-format dump of `poc_quarkus_funqy_ia`.
- Created from the running PostgreSQL 17 service before changing its image.
- Copied out of the database container to a local, ignored workspace file.
- Restored into a newly initialized PostgreSQL 18 database using the same
  local development user and `pg_restore --no-owner`.
- The prior PostgreSQL 17 volume remains untouched.

### Verification snapshot

CSV exports of `tasks(id, title, created_at)` ordered by `id` are produced
before and after the restore. Compare both exports to verify row count and
task contents. The exports and dump are local verification data and must not
be committed.
